    Getting Started

    xlpro is actively being developed so this page may not be fully up to date.

    Installation

    1. Visit the download page to download the latest release.

    2. Run the installer

    3. Configure the Excel Trust Center Settings within Excel to trust access to the VBA project model.

    All done! Open up a workbook and you should see the xlpro ribbon in Excel

    Enable Trust Access to the VBA Object Model

    xlpro currently uses dynamically allocated VBA modules to register UDFs while the background Python server is running. This requires access to the VBA object model, which can expose your machine to attacks

    1. Start Excel
    2. Open a workbook
    3. Click File > Options
    4. Navigate to the Trust Center tab
    5. Click Trust Center Settings...
    6. Navigate to the Macro Settings tab
    7. Check the box Trust access to the VBA project object model

    Update Pending

    xlpro will soon not require access the VBA object model. Once complete, this can be revoked.

    Quick-Start

    First time user? Open the example workbook c:/users/<USERNAME>/.xlpro/examples/xlpro_example1.xlsx

    Initialization

    Click the xlpro_init ribbon button. This will prompt you to configure a python installation >=3.8. Select the recommended option to install the our recommended python version python 3.13.

    The workbook is now ready to run code. xlpro has created a /book1.xlsx.xlpro folder next to book1.xlsx ready to be used in VSCode.

    Development

    Click the start_vscode ribbon button to open up the ./book1.xlsx.xlpro/ directory in VSCode (or you can do this manually).

    User Defined Functions

    Write any functions in functions.py that you wish to be accessible as User Defined Functions (UDFs) in Excel.

    Run the Server

    xlpro deploys a background python server (based on whichever was selected above) which has two functions:

    1. Executing your Python code
    2. Updating/registering the Excel UDFs

    Click the xlpro_start to start the server - this will start a shell window which is the python process. As long as this window is running, the Python server is running.

    Reload Functions

    Click the xlpro_refresh ribbon button to load/reload your functions into Excel. You can now issue a worksheet recalculate.

    Asynchronous Execution

    xlpro executes the code in a separate thread to Excel, so it has nearly no impact on Excel's responsiveness. You will likely see a placeholder string value appear before you see your function outputs because of this!

    Debugging

    xlpro configures the vscode debugging task to hook onto the running Python background server. In your vscode project for the workbook, navigate to the Run and Debug pane and run the xlpro debugpy while the background server is running.

    Add a breakpoint to a function being used in Excel - then click refresh and recalculate. You should have entered a breakpoint which you can use for debugging. Note this will pause the background python server.

    Debugging

    IDE debuggers are a great way to debug python code. We recommend entering a breakpoint, and using the variable explorer and debug console to test your code.

    FAQs

    Adding a FAQ section to crudely explain the functionality.

    1. Where is my Python server?

      • The xlpro application creates an isolated virtual environment from xlpro_init. This has its own installed dependencies, and these dependencies are written to the ./*.xlpro/ directory so the environment associated with a workbook can be reproduced.

    2. Can I have multiple workbooks active simultaneously?

      • Yes, workbook background servers are independent.

    3. Why don't recalculates enter my function breakpoints

      • xlpro fundamentally relies on a results cache to keep Excel's main thread free and responsive so Python can work in the background and send its results over when ready.
      • So, if xlpro has already calculated the results of a set of arguments, it will assume the existing calculation is valid (which may not be true if your Python code depends on a random number generator).
      • This cache is cleared when xlpro_refresh is called, so if you want to forcibly recalculate, consider refreshing first.
      • The cache is tagged with a uid based on the caller address, function name and arguments as values, so if the input values change, a recalculate will always be issued.

    4. How does debugging work?

      • xlpro uses the VSCode debugpy module to open a debug server at an available port. Once the server is running, this port is written into ./*.xlpro/.vscode/launch.json each time the server is created, so your debug configuration is updated as needed.

    5. How are dependencies managed?

      • xlpro uses uv to manage dependencies and Python versions. All of your virtual environments are kept within the installation directory /.xlpro/envs/ and a map between the workbooks

    6. xlpro is using a lot of space, how can I reduce it?

      • xlpro will create unique environments as requested by the user, each of these will likely include fully copies of the usual libraries such as matplotlib and numpy for example. This can consume a lot of storage if left unchecked.
      • xlpro supports linking many workbooks to one environment. Consider reusing a standard environment to prevent file duplication.
      • Want to clear the wasted space? Just delete the envs under .xlpro/envs/*. The next time you initialize a workbook xlpro will use the metadata kept with the workbook to create a fresh environment that matches the previous.

    7. Can I reuse a virtual environment for multiple workbooks?

      • Yes, In the xlpro_init dialogue when initializing a workbook, select an existing interpreter for another workbook. This will reduce the size of the xlpro installation directory.

    8. Can I configure a virtual environment somewhere else?

      • Yes, xlpro supports custom virtual environment paths. The xlpro application creates a symbolic link to this environment so it looks the same internally. This environment will need to be modified to install the xlpro Python module and its dependencies.
      • These symlinked environments must be virtual, and cannot be installation-level interpreters. We don't want to modify your system interpreter environment!

    9. Can I configure a standard python version and dependencies for my colleagues?

      • Pending development...
      • Some light modifications to the code can be made to support a default .python-version and requirements.txt on initialization.

    10. What if I lose my local data?

      • No worries! xlpro pushes the latest requirements of the virtual environment to the directory adjacent to the Excel workbook. So as long as you keep the workbook file and the .xlpro folder, you can always recreate your environment.
      • Store your workbooks on a server

    11. Sharing workbooks

      • As you might've read above, xlpro pushes the data needed to recreate the author's Python environment to the xlpro folder. Ship the workbook and xlpro folder together, and others can recreate your configuration in a few clicks.
